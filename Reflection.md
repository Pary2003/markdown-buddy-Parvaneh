# Reflection

## 1. How did your prompt wording affect the quality of the generated R code?

I found that clear and specific prompts produced better results. When I included details about the purpose of the Shiny application, the required sections, and the Markdown formatting, the AI response was more organized and useful. Refining the prompts also helped me improve the structure and clarity of the documentation instead of accepting the first response.

## 2. What debugging step taught you the most about R function logic?

The most useful debugging step was reviewing errors in the R console and checking the code that caused them. For example, I learned that instructions or normal English text should not be entered directly into the R console as R commands. I also checked the Shiny code and its functions before running and previewing the document. This helped me better understand how R interprets commands and how small syntax issues can cause errors.

## 3. How might you verify AI-generated code in a professional analytics setting?

I would never rely on AI-generated code without checking it. I would review the code line by line, run it in a controlled environment, check for errors, and compare the results with the expected output. I would also test different inputs and review the documentation for the R packages and functions being used. For important analytics work, I would use peer review or an independent validation before using the code in production.
